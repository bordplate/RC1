# func_0012DF18 (0x12DF18) — RESOLVED 2026-09-23: dead-tail byte preservation

NOT a function. 4-byte (0x4) unreachable fragment `addiu sp,sp,0x40` at
0x12DF18 (file 0x2EE98) immediately after the matched, frameless
`snd_PrepareReturnBuffer` (0x12DEF8, RTL 0x1C bytes ending `jr ra;
<sw zero,0(a0) delay slot>`, alignment nop at 0x12DF14), plus one 4-byte
alignment nop (0x12DF1C) before the next real function `snd_BankLoadByLoc`
(0x12DF20).

```
0x12DF14: 00000000  nop                 (parent's .align 3 padding)
0x12DF18: 27BD0040  addiu sp,sp,0x40    <- the entire Splat range of func_0012DF18
0x12DF1C: 00000000  nop                 (alignment before 0x12DF20)
```

Member of the ~46 EGC dead-tail "phantom function" artifact family (see
help_msg_string__Fi.md "Systemic" section and 989snd_func_0012E078.md):
the original compiler stranded a 0x40 frame deallocation after the parent's
epilogue; the size matches no frame in the neighborhood.

## Why no C form can regenerate it (2026-09-17 analysis, still valid)

1. The parent `snd_PrepareReturnBuffer` is frameless (first byte `sll
   v0,a1,2`, no prologue); any C form giving it a frame inserts a
   prologue at 0x12DEF8 and breaks its 7 matched words, so the parent can
   never carry the `addiu sp,sp,0x40`.
2. A separate C function in the gap would need a `jr ra` or self-branch at
   0x12DF1C (a nop); a frameless C function cannot contain a bare
   `addiu sp,sp,0x40` at all.
3. Local EGC 2.95.2 v2.73a (project flags) never emits a dead
   `addiu sp,sp,N` after an epilogue: sibling probes (t1-t10) produced
   dead stores only, and a 0x40-frame probe emits a single in-delay-slot
   deallocation, never a stranded one.

## Resolution (per the 2026-09-18 AGENTS.md dead-tail ghost policy)

The orphan `INCLUDE_ASM("code/_generated/nonmatchings/989snd/ee/989snd_mid",
func_0012DF18)` in 989snd_mid.c was replaced by a file-scope `asm(...)`
block placed at the same source position (between snd_PrepareReturnBuffer
and the snd_BankLoadByLoc INCLUDE_ASM). The block reproduces the generated
assembly verbatim: `.align 3` + `nonmatching func_0012DF18, 0x4` +
`glabel func_0012DF18` + `.word 0x27bd0040` + `endlabel` + `.word
0x00000000`, so 989snd_mid.o keeps the exact 8 bytes at object offset 0xB4
(one alignment nop + the two fragment words) and the symbols
func_0012DF18 / func_0012DF18.NON_MATCHING stay defined at 0xB8 exactly as
the generated assembly defined them.

First application of the ghost policy in this TU (the sibling
func_0012DE60 two-deallocate tail was converted the same way on
2026-09-23 with plain `asm("...")` statements at file scope). Per policy
this is NOT a decompilation target and gets NO blocked.json entry; the
stale 2026-09-17 blocked.json entry was removed and the target drops out
of the status tool's count (669 -> 668).

- `nm -n build/code/989snd/ee/989snd_mid.o`: func_0012DF18 /
  func_0012DF18.NON_MATCHING at 0xB8, snd_BankLoadByLoc at 0xC0
  (unchanged from the INCLUDE_ASM baseline).
- `objdump -d` of 989snd_mid.o 0xB4-0xBF: `00000000 27bd0040 00000000`
  (alignment nop + fragment verbatim).
- `make` + `cmp build/boot_elf.elf assets/boot_elf.elf`: byte-identical.
- Durability: `make split` (regenerates code/_generated/ and the .ld),
  rebuild of 989snd_mid.o, `make` + `cmp`: byte-identical again. The
  change lives only in 989snd_mid.c source, so it survives split
  regeneration by construction.
- One pitfall hit during the change: an initial plain
  `asm("addiu $sp,$sp,0x40"); asm("nop");` form WITHOUT the `.align 3`
  shifted the fragment 4 bytes early (no alignment nop at 0x12DF14) and
  broke parity at exactly 0x12DF14-0x12DF17. The `.align 3` from the
  generated .s is load-bearing, not decoration.
