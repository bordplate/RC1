## What it does

`void func_00200078(int frame, int x, int y, int w, int h, int alpha)` (6 int
args; the EE ABI puts the 5th/6th in t0/t1). Computes
`HudFrame* fr = (HudFrame*)(frame*4 + (int)hudHeap.frames)`,
`HudFrameTex* tex = hudHeap.texs + fr->hTex`, `texU = 1<<tex->uLog`,
`texV = 1<<tex->vLog`. Appends a 16-byte header
`[0x10000005, 0, 0, 0x50000005]` plus 10 qwords at head+16 to the
`vu1ChainHead` VU1 chain, then advances the head by 20 qwords (0x50):

- q0 = 0x740000008001  (materialized `li t8,0xE800; dsll32 t8,t8,15; ori t8,t8,0x8001`)
- q1 = 0x5353106
- q2 = GetFrameTex(frame)   (jal 0x1FFA10, **1-arg**; the callee does the whole
      tex/pal lookup itself — it does `sll a0,a0,2` on frame. Lombyte's
      2-arg `(tex,0x10000005)` reconstruction is a Ghidra pseudocode artifact.)
- q3 = 0x156
- q4 = ((u64)alpha<<24) | 0x7F7F7F
- q5 = 0
- q6 = posTL
- q7 = (texV<<20) + (texU<<4)     (int `+`, not `|`, not a (u64) cast)
- q8 = posBR
- q9 = 0

where **posN is a packed (x, y, z) coordinate**:

```
posN = (xN + occlViewParams.minX - 8)
     | ((u64)(yN + occlViewParams.minY - 8) << 16)
     | ((u64)hudHeap.vuField_0C << 32)      // z/blend in the HIGH word
posTL: (x1,y1) = (x, y);    posBR: (x2,y2) = (x+w, y+h)
```

The original emits `lw v0,12(t5); dsll32 v0,v0,0; or r,r,v0` — i.e. it shifts
`vuField_0C` **LEFT BY 32** into the HIGH word before OR-ing it in (both
corners). An earlier candidate used `(u64)z` (low word) which was WRONG and
left the function 4 words short (both `dsll32` missing). Fixing it to
`((u64)hudHeap.vuField_0C << 32)` made the size match (118) and produced both
`dsll32`. `occlViewParams.minX`/`minY` are re-loaded once per corner (4 loads
total) — the original does NOT CSE them. `hudHeap.vuField_0C` is read with
`lw` (not `lwu`) then `dsll32`, so it is a plain (signed) `int`.

All six `vu1ChainHead` loads are self-based absolute (`lui r,0x16; lw r,0xF00(r)`);
the header/qword stores are absolute via `$at`; the final head advance
(`vu1ChainHead += 20`) is a GPREL store. Required head form in this TU: plain
(non-.data) double-volatile `extern volatile u32* volatile vu1ChainHead;`.

## The 48-word residual (all scheduler/RA tie-breaks, 0x2000F4–0x200257)

Decomposes into three coupled EGC 2.95.2 default-scheduler / RA tie-breaks:

1. **y/w s-reg swap**: orig y→s4, w→s3; candidate y→s3, w→s4. A pure
   allocation tie-break (usage order is identical — y used before w in both)
   that propagates through the whole pos block (idx 27,29,70,71,78,80,82,85
   and the posBR ops).
2. **final head load position**: the orig loads `vu1ChainHead` **LATE**
   (0x20024C, into v0) AFTER the posBR computation and q9/q8 stores, keeping
   **a0 free** for the posBR minX load (`lw a0,16(a1)` at 0x2001AC). The
   candidate hoists the head load **EARLY** (0x200200, into a0) right after
   posTL, forcing the posBR minX load into **a2** (`lw a2,16(a1)`) and shifting
   the whole posBR block by a slot.
3. **epilogue lq interleaving**: the orig interleaves `lq ra,144(sp)`
   (0x200200) and `lq s7,128(sp)` (0x200210) WITH the posBR computation; the
   candidate does a tight sequential epilogue (all 9 `lq` restores) at the end.

## What was tried (all regressed or traded one tie-break for another)

- **Lombyte q-store order** (q2,q4,q3,q5,q7,q6,q9,q8): 78 diffs — breaks the
  a0/a1 assignment (needs q2,q3,q4,q5).
- **Inlining color / call result** (no `tex0`/`color` locals, Lombyte-literal):
  78 diffs — shatters the prologue arg→s assignment.
- **Precomputing y+h / x+w into locals** (to force the orig's hoist of the
  posBR adds): 78 diffs — changes the register allocation.
- **or-term reordering** (36 combos via gen_or.py): or_00 (A|B|C) = correct
  `((A|B)|C)` machine or-order, 48 diffs, but y/w swapped; or_10 (TL=A|C|B,
  BR=A|B|C) = correct y/w RA (y→s4,w→s3), 50 diffs, but wrong or-structure
  `((A|C)|B)`. The or-structure and the y/w RA are coupled in EGC and the orig
  decouples them.
- **`register OcclViewParams* vp asm("$5"); vp=&occlViewParams;`** base pin:
  BROKEN in this function — EGC drops the base materialization entirely (assumes
  a1 already holds it) and reuses a1 for the field → miscompile. Works in simple
  probes, not here.
- The head-load-position tie-break (orig late in v0 vs cand early in a0) is only
  controllable with a post-store memory barrier, which (per the sibling)
  perturbs the allocation-sensitive prologue.
