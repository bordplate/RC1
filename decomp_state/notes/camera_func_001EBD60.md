## Identity

Member of the ~46 EGC dead-tail "phantom function" artifact family (see
help_msg_string__Fi.md "Systemic" section and 989snd_func_0012E078.md).
First observed shape in the family combining two `move v0,zero` zero-moves
with one absolute `sw zero,0(a0)` store. The a0 store cannot be parent RTL:
the parent is void with no parameters (Ghidra `void FUN_001ebcf0(void)`;
a0 untouched in the body). Its single caller UpdateAllCameras__Fi (0x1EC504)
is a plain `jal` with no argument setup (delay slot holds `swc1 f1,8(v1)`);
a0 is a stale loop value in the caller, so the store is unreachable RTL
residue of the original Insomniac EGC build, same class as the 989snd
`addiu sp` units.

## Why no C form matches

- Unreachable: no C function can occupy it without a terminator that would
  shift 0x1EBD78.
- Local EGC 2.95.2 never emits post-`jr` dead RTL for any form of the parent
  (the parent's own best form is 106/108 with NO tail; the parent is blocked
  for an unrelated address-splitting conflict, last-resort already used on
  it 2026-09-07).
- A C function with an asm name override cannot suppress EGC's return
  epilogue; a standalone object cannot be placed by the Splat .ld without a
  new subsegment; extending the parent's generated .s range is not durable
  (code/_generated/ is regenerated by `make split`).

## Resolution (per the 2026-09-18 AGENTS.md dead-tail policy and the
actuator.cpp/stash.cpp file-scope asm precedent)

The orphan `INCLUDE_ASM("code/_generated/nonmatchings/game/camera",
func_001EBD60)` in camera.cpp was replaced by a file-scope `asm(...)` block
that emits the six words verbatim (`.word` form, no mnemonics) between the
parent's INCLUDE_ASM and Cam_InterpValues' INCLUDE_ASM, so camera.o's .text
keeps the exact 24 bytes at object offset 0xD0. The block carries
`nonmatching func_001EBD60, 0x14` + `glabel func_001EBD60` so the symbols
remain defined in camera.o exactly as the generated assembly defined them,
and `.align 3` + the trailing nop preserve the 8-byte alignment into
Cam_InterpValues.

This is the first application of the 2026-09-18 "explicit inline assembly"
policy (actuator.cpp's func_001E8D00 phantom and stash.cpp's boundary nops
already use plain `asm("nop")` at file scope for the same purpose). Per that
policy this is NOT a decompilation target and gets NO blocked.json entry;
the target drops out of the status tool's count (678 -> 677, active 642 ->
641).
