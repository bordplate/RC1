# func_0022DD78 (vram 0x22DD78, file 0x12ECF8, 0x18) — matched 2026-09-05

## Semantics

Callback registered with the 989snd bank loader. Truncates its 64-bit second
argument to 32 bits and, if the result is non-zero, stores its first argument
at that address:

```c
extern "C" void func_0022DD78(int a, long b) {
    int c = (int)b;
    if (c)
        *(int*)c = a;
}
```

Replaced in `code/game/sound.cpp` (placeholder was line 33). Kept
`extern "C"` + the `func_` name because the included assembly of
`func_00204428` (game/loaders) and `func_00230F60` (game/space) references the
symbol unmangled via `%hi`/`%lo`; a mangled C++ name breaks the link
(undefined reference to `func_0022DD78`).

## Findings

- No direct `jal`/`j` xrefs in the boot ELF or any level overlay: it is
  invoked indirectly. `func_00230F60` (0x231588) and `func_00204428`
  (0x20470C) load `&func_0022DD78` into `$a0` and pass it as the callback
  argument to `snd_BankLoadFromEE_CB` (0x12E088), which stores it in
  D_00137B40 and clears D_0015ED00/D_0015ECD8. `snd_FlushSoundCommands`
  (0x12DD70) later loads the stored callback, clears D_0015ED00/D_0015ECD8,
  and `jalr`s it with `a1 = D_0015ECD8` (the 64-bit bank data pointer).
- The leading `dsll32/dsra32` identity pair is EGC's 64-to-32-bit truncation
  of the `long` parameter (shamt 0, in-place on `$a1`); it is what separates
  this family from the plain `if (x) *x = a;` shape. Siblings
  `func_0022DD90`/`func_0022DDD8` share the same truncation prologue and
  operate on the same slot struct (fields at 0, 4, 0x18, 0x1c).
- EGC 2.95.2 EE quirk: `if (c) *(int*)c = a;` (32-bit condition) compiles to
  `bnezl c,+8` with the store in the branch DELAY slot, so the store executes
  unconditionally and the branch is a no-op jump. The C condition written in
  the source is the inverse of the emitted branch sense; the emitted bytes
  are the oracle and match exactly. Several source forms compile
  byte-identical (verified with the local EGC: `int c = (int)b; if (c)
  *(int*)c = a;`, `if ((int)b) *(int*)b = a;`, `int c = b; ...`); the first
  was kept. `void*`-parameter forms do NOT emit the truncation pair and do
  not match.
