## Solved: CSE merge of the two `*0x15EEB0` loads
The natural form (no asm) makes EGC 2.95.2's CSE pass merge the second
constant-address materialization into the first's register:
- Cost model (gcc/cse.c): `COST(const_int)=2`, `COST(pseudo)=1`, `COST(hard reg)=2`.
- Replacement (mat2 -> mat1's reg) happens when the table register is **cheaper** than the const.
- Natural form: mat1's dest is a pseudo (cost 1 < 2) -> merged -> shared base reg
  (`lw $17,0($16)` for both loads) + 3-register frame (ra,s0,s1) = 0x30 / 108 bytes.

Fix: force the mat into a HARD register. `register int addr asm("$16") = 0x15EEB0;`
makes mat1's dest a hard reg (cost 2). The 2-vs-2 **tie** stops the replacement, so
mat2 keeps its own constant -> two separate self-overwrite `lui/lw` pairs and a
2-register frame (ra,s0) = 0x20 / 100 bytes. This matches the original's load/frame
shape. (Named symbol `extern int D_0015EEB0;` gives a single gp-relative `lw` = 92B, wrong.)
